# 記事抽出ライブラリ比較

## 比較方法

`scripts/compare_extractors.py` を使い、記事、技術資料、表中心ページを各10回処理した。
重要文字列の保持率、HTML 構造の保持数、実行時間の中央値を比較した。計測環境は
Python 3.14、trafilatura 2.2.0、readability-lxml 0.9 である。

## 結果

| fixture | 抽出器 | 重要文字列 | 見出し | code 要素 | table | image | 中央値 (ms) |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 記事 | trafilatura | 100% | 0 | 0 | 0 | 0 | 3.194 |
| 記事 | readability-lxml | 100% | 1 | 0 | 0 | 1 | 0.752 |
| 技術資料 | trafilatura | 50% | 0 | 0 | 0 | 0 | 4.418 |
| 技術資料 | readability-lxml | 100% | 2 | 2 | 0 | 0 | 1.017 |
| 表中心 | trafilatura | 100% | 0 | 0 | 0 | 0 | 4.388 |
| 表中心 | readability-lxml | 100% | 1 | 0 | 1 | 0 | 1.001 |

小さな fixture のマイクロベンチマークであり、絶対時間や実サイトでの順位を保証する結果ではない。
一方、今回重視するコード、表、画像、見出しの保持では readability-lxml が一貫して優れた。

## 採否

`readability-lxml` を採用する。Python 3.14 で導入・実行でき、比較対象では重要文字列をすべて保持し、
構造要素も維持した。`trafilatura` は記事本文の抽出には利用できるが、HTML 出力でも技術資料の
コードと複数の構造要素を失うため不採用とする。

readability の出力も無条件には採用しない。既存の品質指標を満たすときだけ使用し、品質不足時は
DOM 候補、さらに候補が不適切なときは full document へ fallback する。
